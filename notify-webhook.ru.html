Webhook — своё подключение

Бот отправляет JSON POST на ваш адрес: {"rig": "…", "text": "…"}. Подходит для Home Assistant, n8n, Zapier и любого скрипта.

Как подключить

  1. Подготовьте приёмник

    HTTP(S) endpoint, доступный с рига (открытый URL). Один POST — одно уведомление.

  2. Подключите бот

    В Telegram у OCBot: /notify webhook URL.

  3. Проверьте

    /notify test — приёмник получит {"rig":"имя рига","text":"пробное сообщение"}.

Формат и примеры

Content-Type: application/json. Тело запроса:

{
  "rig": "rig1",
  "text": "Карта 3: отвал, перезагрузка рига"
}

Примеры приёмников:

  • Home Assistantтриггер «webhook» → действие-уведомление / сценарий
  • n8n / Zapier / Makeузел Webhook → любые действия
  • Свой скриптлюбой сервер: POST-эндпойнт, далее — что хотите
  • Проверить вручнуюcurl -H 'Content-Type: application/json' -d '{"rig":"t","text":"ok"}' URL

Разделение уведомлений

В каждом запросе всегда есть rig (имя рига) и text (содержание). Ошибки канала показывает /notify test. Отключение: /notify off webhook. Управление ботом через webhook НЕ доступно — только уведомления.

Частые вопросы

http или https?

Любой URL, доступный с рига; для приватных систем крайне желателен https.

Endpoint недоступен

Бот не роняет процесс: ошибка пишется в лог и показывается в /notify test. На время ремонта отключите канал: /notify off webhook.

Пришло не то, что ждал

Проверьте обработчик: текст уходит в поле «text», имя рига — в поле «rig» (Content-Type — application/json).

Гарантия доставки есть?

Нет: одна попытка с таймаутом 8 сек. Повторы настраивайте на стороне приёмника — или используйте ntfy.

Правила: подключение — /notify …, проверка — /notify test, отключение — /notify off канал; все условия и отказ от ответственности — в инструкции.

Индивидуальный проект: не связан с Hiveon и HiveOS и не спонсируется ими; их названия принадлежат их владельцам.
