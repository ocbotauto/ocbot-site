GDDR6X memory: why it runs hotter than the die and what to do about it

A community classic: sensors read "70 and below", miner looks calm — and a year later the card is tired, because the actual hotspot was not where anyone looked. On GDDR6X cards the hottest node is not the graphics die but the memory itself: high heat density and the worst path of escaping the board. Here is why, how to see the real memory temperature, and what an ordinary owner can do to cool it.

The short version (for the no-time-to-read)

  • GDDR6X runs hotter than the die. The PAM4 signaling scheme moves more data per clock and burns more power: more heat in the same little package than the GPU's core generates.
  • The sensor you usually watch is the die's sensor. Many cards do not expose memory temperature at all, or expose it as a separate field (junction temperature) in advanced monitoring tools; miner logs often omit it entirely.
  • Memory heat escapes through thermal pads. Factory pads that are thin or dried out leave the memory tens of degrees hotter than necessary; replacing pads is the single most effective non-overclocking "upgrade".
  • Memory OC is a direct heater. Higher memory clocks mean higher memory power draw and temperature. Physics does not do exceptions — see our article on temperatures and lifespan.
  • Overheating memory means errors and decay. Exact thresholds are not published by vendors, but "hot memory — slipping stability" is familiar to anyone who chased crashes in summer.

Why the memory runs hotter

Once upon a time the GPU die was the only hot node: GDDR5 was modest in its appetites. GDDR6X introduced PAM4 signaling: more data per clock than the classical scheme — faster, and... hotter. Add placement density: the memory chips sit shoulder-to-shoulder near the core, and their heat has to travel outward through a multilayered PCB.

The practical consequence: a card whose die reads 70 °C may carry memory at 90–100 °C — with everything on the surface looking "fine". Remember: the die temperature you see reflects a well-cooled heatsink plate; the memory underneath lives its own life.

How to see the real memory temperature

  1. Look for the junction field

    On many GDDR6X cards, monitoring tools (HWiNFO64, several miners) expose "memory junction temperature" as a separate value. If the field exists — watch it, not the usual die temperature.

  2. Compare it with the die

    Memory 20–30 °C above the die is a normal GDDR6X picture. A wider gap means degraded pads and/or airflow.

  3. Watch the trend, not one value

    A single number is a moment; the interesting part is whether memory temperature is creeping up at the same overclock over weeks. Growth = cooling path degradation (see our fans article).

Thermal pads: the memory's main "upgrade"

Memory pushes its heat through pads into the cooler plate, and from there into the air. Factory pads are made as cheaply as possible: thin, stiff, low thermal conductivity. The result — the memory runs a dozen-plus degrees hotter than it could.

Replacing pads is the most effective non-tuning procedure for GDDR6X cards:

  • thickness matters — too thin and there is no contact, too thick and the gap is stressed; match it to the specific card;
  • thermal conductivity is not marketing. The difference between "1 W/m·K" and "12 W/m·K" is real and visible in degrees;
  • check the die's interface too — that one is paste, not pads; refreshing it in the same visit makes sense;
  • dust and fans on schedule — a dusty heatsink nullifies even perfect pads.

The procedure takes about an hour and usually surprises more than any OC: minus 10–15 °C on the memory is an ordinary, not extreme, result.

Memory OC and temperature: a direct link

Raising memory frequency increases the memory's power draw and temperature — a miner may still choose to OC, but should know what it costs in heat. Practical guidance:

  • find the point where hashrate no longer rises with memory: past it you add only heat;
  • in summer heat, backing off the memory overclock buys back degrees with almost no hashrate loss;
  • read it in combination: raised memory, memory temperature climbed without a hashrate gain — the point was unnecessary.
